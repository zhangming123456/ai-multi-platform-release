# AI 多平台文案创作功能

## 1. 方案概述

本方案为 AI 图文多平台文案自动生成功能标准化方案，采用**前端图片 Base64 直传模式（无文件服务器）**，依托视觉大模型实现一键生成小红书、抖音、视频号、公众号、朋友圈、微博差异化文案。本文档覆盖产品设计、技术架构、接口协议、Prompt 工程及校验容错机制。

---

## 2. 产品设计

### 2.1 功能定位

基于用户上传图片、关键词、营销活动信息，全自动批量生成多平台差异化合规种草文案，提升新媒体内容产出效率，统一平台内容风格标准。

### 2.2 核心能力

| 能力           | 说明                                         |
| -------------- | -------------------------------------------- |
| 本地图片解析   | 前端 Base64 本地处理，无需文件存储服务       |
| 多维组合创作   | 支持图片、关键词、平台、活动、版本数组合输入 |
| 平台差异化输出 | 各平台独立风格适配，贴合各平台流量与用户习惯 |
| 多版本备选     | 单平台支持多版差异化文案生成                 |
| 结果可复用     | 支持在线编辑、单平台重生成、一键复制         |

### 2.3 输入规范

| 输入项   | 必填 | 约束规则                                                     |
| -------- | ---- | ------------------------------------------------------------ |
| 参考图片 | 否   | 最大 10 张、单张≤5MB、JPG/PNG/视频、Base64 传输不落地        |
| 创作主题 | 否   | 文本描述，支持 `#标签` 提取关键词，定义产品、风格、营销属性  |
| 发布平台 | 是   | 至少选择 1 个，支持多选，目前支持 4 个平台                   |
| 关联活动 | 否   | 系统活动列表选择，选择后自动注入活动背景、宣发图、地点等信息 |
| AI 模型  | 是   | 从已启用的模型配置中选择，需支持文生文或视觉模型             |

### 2.4 输出规范

统一输出结构：**标题 + 正文 + 话题标签**，字段完整无冗余。

#### 平台风格摘要

| 平台   | 枚举值           | 风格描述                       |
| ------ | ---------------- | ------------------------------ |
| 小红书 | `xiaohongshu`    | 种草生活化、带 emoji、氛围感强 |
| 抖音   | `douyin`         | 钩子开头、短句快节奏、亮点前置 |
| 视频号 | `wechat_video`   | 生活化低营销、适配私域         |
| 公众号 | `wechat_mp`      | 正式严谨、适配官方推文         |
| 朋友圈 | `wechat_moments` | 极简精炼、适合转发             |
| 微博   | `weibo`          | 年轻活泼、高互动、强话题性     |

> **当前实现状态**：目前已实现 **4 个平台**（小红书、抖音、视频号、公众号），朋友圈和微博的平台适配待开发。

### 2.5 业务流程

```
信息录入 → 图片转 Base64 → 表单校验 → SSE 流式请求 → 后端组装 Prompt 调用大模型 → 数据容错解析 → 前端实时渲染 → 二次编辑/复制/重生成
```

## 3. 技术架构

### 3.1 架构设计

三层轻量化架构，无文件服务器、无图片存储：

```
┌─────────────────────────────────────────────────────────────┐
│                    前端层 (Vue 3 + Arco)                      │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐    │
│  │ 表单交互  │  │ Base64   │  │ SSE 流式  │  │ 结果渲染  │    │
│  │          │  │ 编解码   │  │ 接收     │  │ 预览编辑  │    │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘    │
└──────────────────────────┬──────────────────────────────────┘
                           │ SSE / HTTP
┌──────────────────────────▼──────────────────────────────────┐
│                    服务层 (Go + Beego)                        │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐    │
│  │ 参数校验  │  │ Base64   │  │ Prompt   │  │ JSON     │    │
│  │          │  │ 鉴权     │  │ 组装     │  │ 容错解析  │    │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘    │
└──────────────────────────┬──────────────────────────────────┘
                           │ OpenAI 兼容 API
┌──────────────────────────▼──────────────────────────────────┐
│                   AI 推理层 (大模型 API)                       │
│  ┌──────────────────────────────────────────────────────┐    │
│  │  Qwen-VL / GPT-4V / DeepSeek / 智谱 / Moonshot ...   │    │
│  │  图文理解 + 多平台文案生成                            │    │
│  └──────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 核心技术约束

- **图片全程前端本地处理**：不上传服务器、不落地存储、不缓存、不存 CDN
- **浏览器 Blob 预览**：操作后主动释放内存，防止泄漏
- **后端仅单次使用 Base64 数据**：请求结束立即销毁，不持久化
- **SSE 流式输出**：各平台结果逐平台实时推送，前端逐字渲染，提升用户体验
- **Function Calling 强制工具调用**：通过 `tool_choice: { type: "function", function: { name: "submit_content_variant" } }` 约束模型输出结构化 JSON

### 3.3 AI 日志规范

- 每次 AI 调用在 `backend-go/logs/ai/` 目录下生成独立的 request 和 response 日志文件
- 日志按天分片，文件名格式：`{时间戳}_{类型}.request.log` / `{时间戳}_{类型}.response.log`
- 日志中的 base64 内容（含 `data:image/...;base64,...` 和纯长 base64 字符串）自动替换为 `[base64:<长度>]` 占位符

### 4.2 核心组件

| 组件                  | 功能                                                 |
| --------------------- | ---------------------------------------------------- |
| `AttachmentInputArea` | 多文件上传区域，支持图片/视频，自动压缩，Base64 编码 |
| `PlatformIcon`        | 平台图标组件，支持各平台标识                         |

### 4.3 关键交互逻辑

#### 图片 Base64 编码流程

```typescript
// 1. 图片压缩（最大 1920px 宽，quality 0.8）
compressImage(file, maxWidth = 1920, quality = 0.8) → File

// 2. 文件转 Base64（去除 data:image/...;base64, 前缀）
fileToBase64(file) → { data: string, mime_type: string }

// 3. URL 素材转 Base64（跨域获取）
fetchUrlToBase64(url) → { data: string, mime_type: string } | null
```

#### 表单校验规则

```
- 平台：至少选择 1 个
- 图文二选一：关键词或上传文件至少填一项
- 图片规格：单张≤5MB，最多 10 个文件
- 模型：必须选择已启用的模型配置
- 防重复提交：生成过程中禁用发送按钮
```

#### SSE 流式接收

使用 `EventSource` 兼容的 fetch + ReadableStream 方案：

```
事件类型:
  - log:     后端日志消息（info/req/ok/err 级别）
  - chunk:   内容逐字增量（实时流式渲染）
  - done:    单平台生成完成（含完整 variant）
  - error:   单平台生成失败
  - complete:全部平台生成完成
```

### 4.4 数据流

```
用户输入 → 表单校验 → 构建请求体
  ├─ topic: 用户输入主题（去除 #标签 后的纯文本）
  ├─ keywords: 从 #标签 提取的关键词数组
  ├─ platforms: 选中的平台枚举数组
  ├─ files: 图片/视频的 Base64 编码数组
  ├─ plan_id: 模型配置 ID
  ├─ model_id: 模型 ID
  └─ campaign_id: 关联活动 ID（可选）
       ↓
POST /api/contents/ai-generate-stream (SSE)
       ↓
SSE 事件流 → 实时渲染 → 操作按钮（复制/保存）
```

## 5. 后端实现

### 5.1 API 接口定义

#### 内容 CRUD

| 方法   | 路径                | 功能                               | 鉴权                   |
| ------ | ------------------- | ---------------------------------- | ---------------------- |
| GET    | `/api/contents/`    | 内容列表（支持平台/状态/活动筛选） | `content:read`         |
| POST   | `/api/contents/`    | 创建内容                           | `content:create:write` |
| GET    | `/api/contents/:id` | 内容详情                           | `content:read`         |
| PUT    | `/api/contents/:id` | 更新内容                           | `content:update:write` |
| DELETE | `/api/contents/:id` | 删除内容                           | `content:delete:write` |

#### 内容创建请求

```json
{
  "title": "string (必填)",
  "body": "string",
  "platform": "string (平台枚举)",
  "status": "string (默认 draft)",
  "media_urls": "string (JSON 数组)",
  "campaign_id": "string (可选)"
}
```

#### AI 生成接口

**非流式**（单平台，兼容旧版）：

| 方法 | 路径                        | 功能             |
| ---- | --------------------------- | ---------------- |
| POST | `/api/contents/ai-generate` | 单平台非流式生成 |

请求参数：

```json
{
  "topic": "string (创作主题)",
  "platform": "string (平台枚举)",
  "style": "string (可选额外风格)",
  "keywords": ["string"],
  "count": "int (生成版本数，默认3)",
  "plan_id": "string (模型配置ID)",
  "campaign_id": "string (可选活动ID)"
}
```

**流式**（推荐，支持多平台）：

| 方法 | 路径                               | 功能                  |
| ---- | ---------------------------------- | --------------------- |
| POST | `/api/contents/ai-generate-stream` | 多平台流式生成（SSE） |

请求参数：

```json
{
  "topic": "string (创作主题)",
  "platforms": ["string (平台枚举数组)"],
  "style": "string (可选)",
  "keywords": ["string"],
  "plan_id": "string (模型配置ID)",
  "model_id": "string (模型ID)",
  "files": [
    {
      "data": "string (Base64 编码数据)",
      "mime_type": "string (MIME 类型)"
    }
  ],
  "campaign_id": "string (可选活动ID)"
}
```

SSE 响应格式：

```
event: log\ndata: {"level":"info","message":"..."}\n\n
event: chunk\ndata: {"platform":"xiaohongshu","text":"..."}\n\n
event: done\ndata: {"platform":"xiaohongshu","variant":{"title":"...","body":"...","hashtags":["..."]}}\n\n
event: error\ndata: {"platform":"xiaohongshu","message":"...","available_plans":[...]}\n\n
event: complete\ndata: {"message":"全部生成完成"}\n\n
```

注入内容包含：

- 活动介绍（Description）

- 面向平台列表
- 活动宣发图（自动加载为多模态素材）

### 5.5 模型配置解析

`ResolveModelConfig(planID, modelID string)` 解析模型配置，返回：

| 返回值            | 类型   | 说明                |
| ----------------- | ------ | ------------------- |
| `api_key`         | string | API 密钥            |
| `base_url`        | string | API 基础地址        |
| `model`           | string | 模型名称            |
| `plan_name`       | string | 配置名称            |
| `supports_vision` | bool   | 是否支持视觉/多模态 |

`parseModelField(raw string)` 解析模型字段，兼容 JSON 数组格式和旧版逗号分隔格式：

- JSON 数组格式：`[{"id":"gpt-4o","types":["text","vision"]}]`
- 逗号分隔格式：`"gpt-4o,deepseek-chat"`

## 6. AI Prompt 工程

### 6.1 System Prompt

```text
你是一个专业的社交媒体内容创作助手，擅长为不同平台生成适配的优质内容。
使用中文回复。必须且只能调用 submit_content_variant 工具返回结构化结果，
禁止输出工具调用以外的任何解释性文字、markdown 代码块或普通文本。
```

### 6.2 用户 Prompt（动态注入变量）

```text
请为以下主题生成一篇适合{platform}发布的内容。
风格要求：{platformStyle}{keywordsStr}

主题：{subject}{fileHint}{campaignHint}

请直接调用 submit_content_variant 工具提交结果，数据结构必须包含：
- title（标题）
- body（正文）
- hashtags（推荐话题标签列表，3-5 个，不含 # 前缀）
禁止输出工具调用以外的任何解释性文字、markdown 代码块或普通文本。
```

### 6.3 动态变量

| 变量              | 说明                                    | 来源                    |
| ----------------- | --------------------------------------- | ----------------------- |
| `{platform}`      | 目标平台中文名                          | `platformLabels` 映射   |
| `{platformStyle}` | 平台风格描述                            | `platformStyleMap` 映射 |
| `{keywordsStr}`   | 关键词提示（如 `，关键词：穿搭, 夏季`） | 用户输入 `#标签`        |
| `{subject}`       | 创作主题                                | 用户输入文本            |
| `{fileHint}`      | 多模态素材提示                          | 上传文件时附加          |
| `{campaignHint}`  | 活动背景注入                            | 关联活动时加载          |

### 6.4 Function Calling 工具定义

```json
{
  "type": "function",
  "function": {
    "name": "submit_content_variant",
    "description": "提交 AI 生成的内容变体（含标题、正文、推荐话题标签）",
    "parameters": {
      "type": "object",
      "properties": {
        "title": { "type": "string", "description": "内容标题，简洁有吸引力" },
        "body": { "type": "string", "description": "内容正文" },
        "hashtags": {
          "type": "array",
          "description": "推荐话题标签列表，3-5 个，不含 # 前缀",
          "items": { "type": "string" }
        }
      },
      "required": ["title", "body", "hashtags"]
    }
  }
}
```

### 6.5 强制约束

- `tool_choice` 强制调用 `submit_content_variant` 工具
- `temperature` 设置为 0.4（兼顾创造性与稳定性）
- `max_tokens` 设置为 8000（确保长内容完整输出）
- 不支持强制工具调用的模型自动降级为自动模式，并输出警告日志

## 7. 校验与容错机制

### 7.1 前端校验

| 校验项     | 规则                           |
| ---------- | ------------------------------ |
| 平台必选   | 至少选择 1 个平台              |
| 图文二选一 | 关键词或上传文件至少填一项     |
| 图片规格   | 单张≤5MB，最多 10 个文件       |
| 模型必选   | 必须选择已启用的模型配置       |
| 防重复提交 | 生成过程中禁用发送按钮         |
| 模型兼容性 | 上传文件时模型必须支持视觉能力 |

### 7.2 后端校验

| 校验项         | 规则                               |
| -------------- | ---------------------------------- |
| Base64 合法性  | 校验 Base64 编码格式               |
| 参数合规       | topic/platforms/files 至少一项非空 |
| 模型配置存在性 | 验证 plan_id 对应的配置存在        |
| 视觉模型检查   | 上传文件时验证模型支持视觉能力     |

### 7.3 异常兜底

| 异常场景               | 处理方式                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------- |
| 报文过大               | 限制单次 10MB，后端 Nginx/网关层限制                                                        |
| 模型返回格式异常       | JSON 容错解析（`stripCodeFence` + `parseContentVariantArgs`），失败时给出可切换模型配置建议 |
| 图片解析失败           | 跳过失败图片，不影响其他素材处理                                                            |
| 空输入                 | 拒绝请求，返回明确错误提示                                                                  |
| 模型配置不存在         | 返回可用模型配置列表，前端 Message 提示切换                                                 |
| 网络超时               | 120s 超时，前端显示超时错误                                                                 |
| 模型不支持 tool_choice | 自动降级为自动模式，不影响生成                                                              |

### 7.4 JSON 容错解析逻辑

```go
// 1. 优先解析 tool_calls 中的 arguments
// 2. 回退解析完整响应文本（stripCodeFence + 尝试 JSON 解析）
// 3. 单变体回退：解析单个 {title, body, hashtags} 对象
// 4. 多变体回退：解析 {variants: [...]} 包装对象
// 5. 全部失败 → 返回错误（含可用模型配置切换建议）
```
