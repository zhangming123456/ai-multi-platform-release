# 权限表达式内置判断函数

> 本文档汇总并规范权限系统中所有内置判断函数的定义、参数及使用方式。
> 适用于接口鉴权、页面路由控制、菜单可见性及页面内操作（按钮级）权限判断。

---

## 一、表达式语法规范

### 1.1 运算符

| 符号 | 含义 | 优先级 | 说明 |
|------|------|--------|------|
| `()` | 分组 | 最高 | 控制求值顺序，括号内优先计算 |
| `!` | 非（NOT） | 高 | 对紧跟其后的权限 Key 或函数调用取反 |
| `&` | 且（AND） | 中 | 左右两侧条件必须同时满足 |
| `\|\|` | 或（OR） | 低 | 左右两侧条件满足其一即可 |

### 1.2 表达式构成

表达式由**权限 Key** 和**内置函数调用**通过运算符组合而成：

```
<表达式> ::= <条件> ( <运算符> <条件> )*
<条件>   ::= <权限Key> | <函数调用> | '!' <条件> | '(' <表达式> ')'
```

**示例：**

```
users:delete:write & !isBuiltInAdmin(user_id) & !isSelf(user_id) & (isAdmin() || hasSameRole(target_user))
```

### 1.3 求值顺序

以 `users:delete:write & !isBuiltInAdmin(user_id) & !isSelf(user_id) & (isAdmin() || hasSameRole(target_user))` 为例：

1. 先计算括号内：`isAdmin() || hasSameRole(target_user)`
2. 再计算取反：`!isBuiltInAdmin(user_id)`、`!isSelf(user_id)`
3. 最后从左到右按 `&` 连接所有条件

## 二、内置判断函数总表

| 分类 | 函数名 | 参数形式 | 返回值 | 说明 |
|------|--------|----------|--------|------|
| 身份认证 | `isAuthenticated` | `isAuthenticated()` | `boolean` | 当前用户 JWT 校验通过 |
| 身份认证 | `isSuperAdmin` | `isSuperAdmin()` 或 `isSuperAdmin(user_id)` | `boolean` | 目标用户是否为超级管理员（role=admin 且 ID="1"） |
| 身份认证 | `isAdmin` | `isAdmin()` 或 `isAdmin(user_id)` | `boolean` | 目标用户是否为管理员（role ∈ [admin, manager]） |
| 身份认证 | `isSelf` | `isSelf()` 或 `isSelf(user_id)` | `boolean` | 目标用户是否为当前登录用户自身 |
| 身份认证 | `isBuiltInAdmin` | `isBuiltInAdmin()` 或 `isBuiltInAdmin(user_id)` | `boolean` | 目标用户是否为内置超级管理员（ID="1"） |
| 角色类型 | `isAdminType` | `isAdminType(role_type)` | `boolean` | 角色类型是否为 "admin" |
| 角色类型 | `isOtherType` | `isOtherType(role_type)` | `boolean` | 角色类型是否为 "other" |
| 资源所有权 | `isOwnContent` | `isOwnContent(content)` | `boolean` | 当前用户是否为指定内容的创建者 |
| 资源所有权 | `isOwnAccount` | `isOwnAccount(account)` | `boolean` | 当前用户是否为指定平台账号的创建者 |
| 角色关系 | `hasSameRole` | `hasSameRole(target_user)` | `boolean` | 当前用户与目标用户是否有交集角色 |

## 三、函数详细说明

### 3.1 身份认证类

#### `isAuthenticated()`

| 属性 | 说明 |
|------|------|
| 参数 | 无 |
| 返回值 | `true` / `false` |
| 实现逻辑 | 当前请求携带的 JWT Token 校验通过 |
| 使用场景 | 需要确认用户已登录的接口或页面，如通知模块、个人中心 |

**典型表达式：**

```
isAuthenticated()
```

---

#### `isSuperAdmin(user_id?)`

| 属性 | 说明 |
|------|------|
| 无参形式 | `isSuperAdmin()` — 判断**当前登录用户** |
| 有参形式 | `isSuperAdmin(user_id)` — 判断**指定用户** |
| 返回值 | `true` / `false` |
| 实现逻辑 | `user.role == "admin"` **且** `user.id == "1"` |

> **注意**：超级管理员是系统中唯一的、ID 固定为 `"1"` 的内置账号，同时具备 `role="admin"`。

**典型表达式：**

```
// 当前用户为超级管理员才可访问
isSuperAdmin()

// 禁止删除超级管理员
users:delete:write & !isSuperAdmin(target_user_id)
```

---

#### `isAdmin(user_id?)`

| 属性 | 说明 |
|------|------|
| 无参形式 | `isAdmin()` — 判断**当前登录用户** |
| 有参形式 | `isAdmin(user_id)` — 判断**指定用户** |
| 返回值 | `true` / `false` |
| 实现逻辑 | `user.role in ["admin", "manager"]` |

**典型表达式：**

```
// 仅管理员可访问
isAdmin()

// 管理员或目标用户自身可查看详情
isAdmin() || isSelf(target_user_id)
```

---

#### `isSelf(user_id?)`

| 属性 | 说明 |
|------|------|
| 无参形式 | `isSelf()` — 比对 `ctx.user_id`（当前上下文中的目标用户ID） |
| 有参形式 | `isSelf(user_id)` — 比对指定用户ID |
| 返回值 | `true` / `false` |
| 实现逻辑 | `current_user.id == target_user_id` |

**典型表达式：**

```
// 用户可编辑自身信息
users:update:write & isSelf()

// 保护用户不可删除自身
users:delete:write & !isSelf(target_user_id)
```

---

#### `isBuiltInAdmin(user_id?)`

| 属性 | 说明 |
|------|------|
| 无参形式 | `isBuiltInAdmin()` — 比对 `ctx.user_id` |
| 有参形式 | `isBuiltInAdmin(user_id)` — 比对指定用户ID |
| 返回值 | `true` / `false` |
| 实现逻辑 | `target_user_id == "1"` |

> **与 `isSuperAdmin` 的区别**：`isBuiltInAdmin` 仅检查用户ID是否为 `"1"`，不校验 `role` 字段。`isSuperAdmin` 是更严格的身份认证。

**典型表达式：**

```
// 禁止删除内置管理员
users:delete:write & !isBuiltInAdmin(target_user_id)

// 禁止修改内置管理员密码
users:change_password:write & !isBuiltInAdmin(target_user_id)
```

---

### 3.2 角色类型类

#### `isAdminType(role_type)`

| 属性 | 说明 |
|------|------|
| 参数 | `role_type` — 字符串，角色的类型标识 |
| 返回值 | `true` / `false` |
| 实现逻辑 | `role_type == "admin"` |
| 使用场景 | 控制管理类型权限的显示与隐藏 |

**典型表达式（前端条件渲染）：**

```
// 当目标角色为 admin 类型时，显示全部权限（含管理类型权限）
isAdminType(role.role_type)
```

---

#### `isOtherType(role_type)`

| 属性 | 说明 |
|------|------|
| 参数 | `role_type` — 字符串，角色的类型标识 |
| 返回值 | `true` / `false` |
| 实现逻辑 | `role_type == "other"` |
| 使用场景 | 非管理类型角色隐藏管理类型权限 |

**典型表达式（前端条件渲染）：**

```
// 当目标角色为 other 类型时，过滤掉 db、api_docs、permissions 等管理类型权限
isOtherType(role.role_type)
```

---

### 3.3 资源所有权类

#### `isOwnContent(content)`

| 属性 | 说明 |
|------|------|
| 参数 | `content` — 内容对象，需包含 `user_id` 字段 |
| 返回值 | `true` / `false` |
| 实现逻辑 | `content.user_id == current_user.id` |
| 使用场景 | 内容详情查看、编辑、删除的权限控制 |

**典型表达式：**

```
// 拥有 content:read 权限，且内容属于当前用户
content:read & isOwnContent(content)

// 仅内容创建者可编辑
content:update:write & isOwnContent(content)
```

---

#### `isOwnAccount(account)`

| 属性 | 说明 |
|------|------|
| 参数 | `account` — 平台账号对象，需包含 `user_id` 字段 |
| 返回值 | `true` / `false` |
| 实现逻辑 | `account.user_id == current_user.id` |
| 使用场景 | 平台账号的详情查看、编辑、删除、状态校验 |

**典型表达式：**

```
// 拥有查看权限，且账号属于当前用户
account:view:read & isOwnAccount(account)

// 仅账号创建者可更新
account:update:write & isOwnAccount(account)
```

---

### 3.4 角色关系类

#### `hasSameRole(target_user)`

| 属性 | 说明 |
|------|------|
| 参数 | `target_user` — 目标用户对象，用于提取其 RBAC 角色集合 |
| 返回值 | `true` / `false` |
| 实现逻辑 | `current_user.roles ∩ target_user.roles ≠ ∅`（两角色集合有交集） |
| 使用场景 | 非管理员用户查看同角色其他用户信息 |

**典型表达式：**

```
// 管理员、用户自身、或同角色用户可查看用户详情
isAdmin() || isSelf(target_user_id) || hasSameRole(target_user)
```

## 四、上下文与传参机制

### 4.1 无参调用（默认上下文）

无参函数默认从**当前请求上下文**中获取当前登录用户信息进行判断：

```javascript
// 以下调用均作用于 current_user
isSuperAdmin()     // 检查 current_user 是否为超级管理员
isAdmin()          // 检查 current_user 是否为管理员
isSelf()           // 比对 ctx.user_id
isBuiltInAdmin()   // 比对 ctx.user_id
```

### 4.2 有参调用（显式指定）

带参数的函数用于比对**显式指定的目标**，常用于列表页每行操作按钮的条件判断：

```javascript
// 比对指定用户ID
isSuperAdmin(user_id)
isSelf(user_id)
isBuiltInAdmin(user_id)
```

### 4.3 上下文传递（前端调用）

前端在调用权限判断时，可通过上下文对象传递额外参数：

```javascript
// 调用示例
permStore.hasPermission('users:delete:write&!isBuiltInAdmin&!isSelf', { user_id: 'xxx' })
```

| 上下文键 | 类型 | 说明 |
|----------|------|------|
| `user_id` | `string` | 目标用户ID，用于 `isSelf()` 和 `isBuiltInAdmin()` 的无参形式比对 |

## 五、常见权限表达式组合

### 5.1 用户管理

| 场景 | 权限表达式 |
|------|------------|
| 查看用户列表 | `users:read & (isAdmin() \|\| isSelf() \|\| hasSameRole(target_user))` |
| 创建用户 | `users:create:write` |
| 编辑用户 | `users:update:write & (isAdmin() \|\| isSelf(user_id) \|\| hasSameRole(target_user))` |
| 更新角色分配 | `users:update:write & isAdmin()` |
| 删除用户 | `users:delete:write & !isBuiltInAdmin(user_id) & !isSelf(user_id) & (isAdmin() \|\| hasSameRole(target_user))` |
| 修改密码 | `users:change_password:write & (isAdmin() \|\| isSelf(user_id))` |
| 自定义权限（查看） | `users:custom_permissions:write \|\| isSelf(user_id)` |
| 自定义权限（编辑） | `users:custom_permissions:write & !isBuiltInAdmin(user_id)` |

### 5.2 内容管理

| 场景 | 权限表达式 |
|------|------------|
| 查看内容列表 | `content:read` |
| 创建内容 | `content:create:write` |
| 编辑内容 | `content:update:write & isOwnContent(content)` |
| 删除内容 | `content:delete:write & isOwnContent(content)` |
| AI生成内容 | `content:ai_generate:write` |

### 5.3 平台账号

| 场景 | 权限表达式 |
|------|------------|
| 查看账号列表 | `account:view:read` |
| 创建账号 | `account:create:write` |
| 查看账号详情 | `account:view:read & isOwnAccount(account)` |
| 更新账号 | `account:update:write & isOwnAccount(account)` |
| 删除账号 | `account:delete:write & isOwnAccount(account)` |
| 校验账号 | `account:check:write & isOwnAccount(account)` |

### 5.4 审核管理

| 场景 | 权限表达式 |
|------|------------|
| 查看审核列表 | `review:read` |
| 提交审核 | `review:submit:write` |
| 通过审核 | `review:approve:write` |
| 驳回审核 | `review:reject:write` |
| 通过SQL变更 | `db_change:approve:write & !isSelf(user_id)` |

### 5.5 系统管理

| 场景 | 权限表达式 |
|------|------------|
| 查看仪表盘 | `dashboard:read` |
| 查看SQL历史 | `db_history:view:read` |
| 执行SQL | `db:execute:write` |
| 维护角色/权限/约束 | `roles:manage:write` / `permissions:manage:write` / `constraints:manage:write` |

## 六、函数与权限 Key 组合优先级详解

以删除用户的完整表达式为例：

```
users:delete:write & !isBuiltInAdmin(user_id) & !isSelf(user_id) & (isAdmin() || hasSameRole(target_user))
```

**分步求值：**

| 步骤 | 计算项 | 结果说明 |
|------|--------|----------|
| 1 | `isAdmin()` | 当前用户是否为管理员 |
| 2 | `hasSameRole(target_user)` | 当前用户与目标用户是否有相同角色 |
| 3 | `isAdmin() \|\| hasSameRole(target_user)` | 步骤1或步骤2满足其一 |
| 4 | `!isBuiltInAdmin(user_id)` | 目标用户不是内置管理员 |
| 5 | `!isSelf(user_id)` | 目标用户不是当前用户自身 |
| 6 | `users:delete:write & 步骤4 & 步骤5 & 步骤3` | 拥有删除权限，且满足4、5、3全部条件 |

## 七、注意事项与最佳实践

1. **命名规范**
   - 权限 Key 使用小写，模块与操作间用冒号 `:` 分隔（如 `users:delete:write`）
   - 内置函数使用 camelCase（如 `isSuperAdmin`、`hasSameRole`）

2. **参数类型**
   - `user_id` 统一为**字符串**类型（如 `"1"`），避免数字与字符串比较导致的不匹配

3. **空值安全**
   - 当目标对象或上下文为空时，判断函数应返回 `false` 而非抛出异常
   - 例如 `isOwnContent(null)` 应返回 `false`

4. **优先级显式化**
   - 复杂表达式建议使用 `()` 显式分组，提高可读性，降低维护成本
   - 推荐：`a & (b || c)`，不推荐依赖默认优先级：`a & b || c`

5. **缓存建议**
   - 用户的权限列表和角色信息建议在登录时计算并缓存
   - 减少重复的数据库查询和角色继承计算

6. **扩展规范**
   - 新增内置函数时，命名应遵循 `isXxx`（状态判断）或 `hasXxx`（关系判断）前缀
   - 必须在本文档中补充定义，并在接口/页面文档中引用

7. **前端与后端一致性**
   - 前端菜单/按钮的可见性判断应与后端接口鉴权保持逻辑一致
   - 避免前端隐藏但后端未鉴权，或前端显示但后端拒绝的情况
