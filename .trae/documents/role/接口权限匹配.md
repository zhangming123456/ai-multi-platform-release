# 接口权限匹配

## 权限判断表达式说明

| 符号   | 含义                        | 优先级 |
| ------ | --------------------------- | ------ |
| `()`   | 分组，强制提升优先级        | 最高   |
| `!`    | 非（NOT），对后面的条件取反 | 高     |
| `&`    | 且（AND），必须全部满足     | 中     |
| `\|\|` | 或（OR），满足任一条件即可  | 低     |

> **优先级示例**：`A & B || C` 等价于 `(A & B) || C`；`!A & B` 等价于 `(!A) & B`。

## 内置判断函数

### 函数列表与参数

> 完整函数定义见 [权限表达式内置判断函数](权限表达式内置判断函数.md)。

| 函数             | 参数形式                                  | 默认 ctx key    | 含义                                       |
| ---------------- | ----------------------------------------- | --------------- | ------------------------------------------ |
| `isAuthenticated` | 无参                                     | —               | 当前用户已登录（JWT 校验通过）             |
| `isSuperAdmin`   | 无参                                      | —               | 当前用户为超级管理员（role=admin，ID="1"） |
| `isAdmin`        | 无参                                      | —               | 当前用户为管理员（role=admin 或 manager）  |
| `isSelf`         | 无参 / `isSelf(key_name)`                 | `user_id`       | 目标用户为当前登录用户自身                 |
| `isBuiltInAdmin` | 无参 / `isBuiltInAdmin(key_name)`         | `user_id`       | 目标用户为内置超级管理员（ID="1"）         |
| `isOwnAccount`   | 无参 / `isOwnAccount(key_name)`           | `account`       | 账号的 user_id 等于当前用户 ID             |
| `isOwnContent`   | 无参 / `isOwnContent(key_name)`           | `content`       | 内容的 user_id 等于当前用户 ID             |
| `hasSameRole`    | 无参 / `hasSameRole(key_name)`            | `target_user`   | 当前用户与目标用户存在共同角色             |
| `isAdminType`    | `isAdminType(role_type)`                  | —               | 角色 role_type 为 "admin"                  |
| `isOtherType`    | `isOtherType(role_type)`                  | —               | 角色 role_type 为 "other"                  |

### 参数说明

- **无参形式**：函数从上下文（ctx）中读取默认 key 对应的值进行判断。
- **有参形式**：参数为 ctx 字典中的 **key 名称**（字符串），函数从 `ctx[key_name]` 取值。
  - 例如 `isSelf(user_id)` → 读取 `ctx["user_id"]` 作为目标用户 ID
  - 例如 `isOwnAccount(acc)` → 读取 `ctx["acc"]` 作为账号对象（需具有 `user_id` 字段）
- **参数不是字面值**：`isSelf("1")` 是错误的用法，应使用 `isSelf(user_id)` 配合 `ctx = { user_id: "1" }`。

### 上下文（ctx）字段定义

#### 前端 PermContext（`frontend/src/utils/permExpression.ts`）

```typescript
export interface PermContext {
  currentUser: { id: string; role: string }  // 必填，由 userStore 自动注入
  user_id?: string                            // isSelf / isBuiltInAdmin 默认读取
  account?: { user_id: string }               // isOwnAccount 默认读取
  content?: { user_id: string }               // isOwnContent 默认读取
  target_user?: { id: string; role: string }  // hasSameRole 默认读取
  current_role_ids?: string[]                 // hasSameRole 当前用户角色集
  target_role_ids?: string[]                  // hasSameRole 目标用户角色集
}
```

#### 后端 context（`backend/app/services/perm_expression.py`）

```python
context: dict[str, Any] = {
    "current_user": User,              # 必填，由 require_permission 自动注入
    "user_id": str,                    # isSelf / isBuiltInAdmin 默认读取
    "account": Account,                # isOwnAccount 默认读取（需有 user_id 属性）
    "content": Content,                # isOwnContent 默认读取（需有 user_id 属性）
    "target_user": User,               # hasSameRole 默认读取
    "all_role_ids": set[str],          # hasSameRole 后备角色集
    "current_role_ids": set[str],      # hasSameRole 当前用户角色集
    "target_role_ids": set[str],       # hasSameRole 目标用户角色集
}
```

> **前后端差异**：前端 `currentUser` 为驼峰，后端 `current_user` 为下划线；前端角色集为 `string[]`，后端为 `set[str]`。

## 使用方式

### 1. 前端权限检查

#### 1.1 路由守卫（`router/index.ts`）

路由守卫自动将 `route.query` 和 `route.params` 合并为 ctx，传递给 `hasPermission`：

```typescript
function hasPerm(to: RouteLocationNormalized): boolean {
  if (to.meta.skipPermCheck) return true
  const permKey = to.meta.permKey as string | undefined
  if (!permKey) return true
  const permStore = usePermissionStore()
  return permStore.hasPermission(permKey, {
    ...(to.query ?? {}),
    ...(to.params ?? {}),
  })
}
```

路由配置示例：

```typescript
{
  path: '/rbac/users/:id/edit',
  component: RBACUserEdit,
  meta: {
    permKey: 'users:update:read || isSelf(user_id)',
    // ctx 中的 user_id 由路由 params.id 自动注入
  },
}
```

#### 1.2 组件内权限检查（`hasPermission`）

```typescript
import { usePermissionStore } from '@/stores/permission'

const permStore = usePermissionStore()

// 单一权限 key
const canCreate = computed(() => permStore.hasPermission('users:create:write'))

// 权限表达式（无内置函数）— 无需传 ctx
const canEdit = computed(() => permStore.hasPermission('users:update:write&isAdmin()'))

// 权限表达式（含 isSelf 等需上下文的函数）— 必须传 ctx
const canEditSelf = computed(() =>
  permStore.hasPermission('users:update:write||isSelf(user_id)', { user_id: userId })
)

// 复合表达式
const canDelete = computed(() =>
  permStore.hasPermission(
    'users:delete:write & !isBuiltInAdmin(user_id) & !isSelf(user_id)',
    { user_id: targetUserId }
  )
)
```

#### 1.3 模板指令（`v-perm`）

```vue
<!-- 单一权限 key -->
<a-button v-perm="'users:create:write'">创建用户</a-button>

<!-- 权限表达式 + 上下文 -->
<a-button
  v-perm="{
    key: 'users:change_password:write || isSelf(user_id)',
    ctx: { user_id: record.id }
  }"
>
  修改密码
</a-button>
```

#### 1.4 权限存储（`stores/permission.ts`）

```typescript
function hasPermission(
  keyOrExpr: string,          // 权限 key 或表达式
  ctx?: PermContext,          // 上下文（可选，表达式含内置函数时必传）
): boolean {
  if (!isExpression(keyOrExpr)) {
    return keyOrExpr in permissions.value    // 单一 key 直接查表
  }
  return evaluatePermission(
    keyOrExpr,
    permissions.value,
    _mergeContext(ctx),                       // 合并默认 ctx（currentUser）
  )
}
```

### 2. 后端权限校验

#### 2.1 装饰器模式（`@RequiresPermissions`）

```python
from app.core.deps import PermAPIRoute, RequiresPermissions

router = APIRouter(prefix="/api/v2", route_class=PermAPIRoute)

# 单一权限 key
@router.get("/users")
@RequiresPermissions("users:read")
async def list_users(...): ...

# 权限表达式（OR 逻辑）
@router.get("/permissions")
@RequiresPermissions("permissions:read||permissions:manage:read")
async def list_permissions(...): ...

# 权限表达式（含内置函数，需传 context）
@router.put("/users/{user_id}/password")
@RequiresPermissions(
    "users:change_password:write||isSelf(user_id)",
    context={"user_id": "path.user_id"},  # 从路径参数提取 user_id
)
async def change_password(...): ...
```

> **注意**：当前后端实际代码中，`@RequiresPermissions` 装饰器主要使用单一权限 key，权限表达式 DSL 主要在前端使用。后端 `require_permission` 已完整支持表达式求值，可通过 `context` 参数传递上下文。

#### 2.2 依赖工厂（`require_permission`）

```python
from app.core.deps import require_permission

# 单一权限 key
@router.get("/users", dependencies=[Depends(require_permission("users:read"))])
async def list_users(...): ...

# 权限表达式
@router.get(
    "/users/{user_id}",
    dependencies=[Depends(
        require_permission(
            "users:read&(isAdmin()||isSelf(user_id))",
            context={"user_id": "path.user_id"},
        )
    )],
)
async def get_user(...): ...
```

#### 2.3 上下文参数提取规则

`context` 参数用于声明如何从请求中提取内置函数所需的上下文值：

| 格式 | 说明 | 示例 |
|------|------|------|
| `"path.{param}"` | 从路径参数提取 | `"path.user_id"` → `request.path_params["user_id"]` |
| `"query.{param}"` | 从查询参数提取 | `"query.filter"` → `request.query_params["filter"]` |
| `"body.{field}"` | 从请求体提取 | `"body.target_id"` → `request_body["target_id"]` |

> **当前实现**：`require_permission` 通过 `context` 参数接收静态字典，由调用方负责构造。路径参数的自动提取需在路由函数内手动传递。

### 3. 表达式求值机制

#### 3.1 前端求值流程

```
hasPermission(keyOrExpr, ctx?)
  ├─ 非表达式 → 查 permissions 字典
  └─ 是表达式 → evaluatePermission(expr, permissions, mergeContext(ctx))
                  ├─ Tokenizer 分词（PERM / FUNC / OR / AND / NOT / LPAREN / RPAREN）
                  ├─ Parser 递归下降解析（expr → andExpr → atom）
                  └─ atom 求值：
                       ├─ PERM → key in permissions
                       ├─ FUNC → BUILTIN_FUNCTIONS[name](args, ctx)
                       ├─ NOT → !atom
                       └─ LPAREN → (expr)
```

#### 3.2 后端求值流程

```
require_permission(key, context?)
  ├─ 非表达式 → 查 flatten_effective_permissions 结果
  └─ 是表达式 → evaluate_permission(expr, flat_perms, eval_ctx)
                  ├─ Tokenizer 分词
                  ├─ Parser 递归下降解析
                  └─ atom 求值：
                       ├─ PERM → key in flat_perms
                       ├─ FUNC → BUILTIN_FUNCTIONS[name](args, ctx, perm_keys, all_role_ids)
                       ├─ NOT → !atom
                       └─ LPAREN → (expr)
```

### 4. 表达式编写规范

1. **运算符必须成对**：`||` 是合法的，单个 `|` 会抛出 `SyntaxError`。
2. **权限 key 与函数的区分**：
   - 含 `:` 的标识符 → 权限 key（如 `users:read`）
   - 后接 `(` 的标识符 → 函数调用（如 `isSelf()`）
   - 在内置函数名集合中的标识符 → 函数（如 `isSelf`、`isAdmin`）
   - 其他标识符 → 按权限 key 处理
3. **函数参数为 ctx key**：参数必须是上下文字典中存在的 key 名称，不能是字面值。
4. **无参函数可省略括号**：`isAdmin` 与 `isAdmin()` 等价；`isSelf` 与 `isSelf()` 等价（使用默认 `ctx.user_id`）。
5. **空格可选**：`A& B` 与 `A & B` 等价，但建议保持一致风格。

## 一、认证模块 `/api/auth`

### 1. 用户登录

- **方法**: POST
- **路径**: `/api/auth/login`
- **描述**: 用户登录，返回 access_token 和用户信息
- **请求体** (`LoginRequest`):
  - `username` (str, 必填): 用户名
  - `password` (str, 必填): 密码
- **响应体** (`LoginResponse`):
  - `access_token` (str): JWT 令牌
  - `token_type` (str): 令牌类型，固定为 "bearer"
  - `user` (`UserInfo`): 用户信息
    - `id` (str): 用户 ID
    - `username` (str): 用户名
    - `email` (Optional[str]): 邮箱
    - `nickname` (str): 昵称
    - `role` (str): 角色标识
    - `avatar_url` (Optional[str]): 头像 URL
    - `created_at` (datetime): 创建时间
- **权限表达式**: 公开，无需权限

### 2. 用户注册

- **方法**: POST
- **路径**: `/api/auth/register`
- **描述**: 用户注册（admin 角色不可通过注册创建）
- **请求体** (`UserCreate`):
  - `username` (str, 必填): 用户名
  - `password` (str, 必填): 密码
  - `nickname` (str, 必填): 昵称
  - `email` (Optional[str], 选填): 邮箱
  - `role` (str, 选填, 默认 "operator"): 角色标识（不可为 admin）
  - `avatar_url` (Optional[str], 选填): 头像 URL
- **响应体** (`UserInfo`): 结构同登录返回的 `user`
- **权限表达式**: 公开，无需权限

### 3. 获取当前用户信息

- **方法**: GET
- **路径**: `/api/auth/me`
- **描述**: 获取当前登录用户信息（含角色和权限枚举）
- **响应体** (`UserInfoWithRoles`): 继承 `UserInfo`，扩展：
  - `roles` (list[`UserRoleRef`]): 角色列表
    - `id` (str): 角色 ID
    - `name` (str): 角色标识
    - `display_name` (str): 角色显示名
  - `permissions` (dict[str, str]): 项目全部权限枚举（key → 资源名）
- **权限表达式**: `isAuthenticated`

### 4. 更新个人信息

- **方法**: PUT
- **路径**: `/api/auth/profile`
- **描述**: 更新当前用户个人信息（昵称、头像）
- **请求体** (`ProfileUpdate`):
  - `nickname` (Optional[str], 选填): 昵称
  - `avatar_url` (Optional[str], 选填): 头像 URL
- **响应体** (`UserInfo`): 更新后的用户信息
- **权限表达式**: `isAuthenticated`

### 5. 修改当前用户密码

- **方法**: PUT
- **路径**: `/api/auth/password`
- **描述**: 修改当前用户密码（需验证旧密码）
- **请求体** (`PasswordChange`):
  - `old_password` (str, 必填): 旧密码
  - `new_password` (str, 必填): 新密码
- **响应体**:
  - `message` (str): 提示信息
- **权限表达式**: `isAuthenticated`

## 二、仪表盘模块 `/api/dashboard`

### 1. 获取仪表盘统计数据

- **方法**: GET
- **路径**: `/api/dashboard/stats`
- **描述**: 获取当前用户的仪表盘统计数据，包括账号总数、今日发布数、待处理任务数、AI 生成内容数、各平台统计及最近发布列表

    - `accounts` (int): 账号数
    - `active` (int): 活跃账号数
    - `articles` (int): 文章数
  - `recent_publishes` (list[`RecentPublish`]): 最近发布（5 条）
    - `id` (str): 任务 ID
    - `title` (str): 内容标题
    - `platform` (str): 平台
    - `account` (str): 账号昵称
    - `status` (str): 任务状态
    - `time` (str): 创建时间（HH:MM）
- **权限表达式**: `dashboard:read`

## 三、平台账号模块 `/api/accounts`

### 1. 获取账号列表

- **方法**: GET
- **路径**: `/api/accounts/`
- **描述**: 获取当前用户的账号列表，可按平台过滤
- **查询参数**:
  - `platform` (str, 选填): 平台过滤
- **响应体**: list[`AccountResponse`]
  - `id` (str): 账号 ID
  - `user_id` (str): 用户 ID
  - `platform` (str): 平台
  - `nickname` (str): 昵称
  - `avatar_url` (Optional[str]): 头像 URL
  - `status` (str): 状态
  - `cookie_data` (Optional[str]): Cookie 数据
  - `access_token` (Optional[str]): 访问令牌
  - `token_expires_at` (Optional[datetime]): 令牌过期时间
  - `last_check_at` (Optional[datetime]): 最后检查时间
  - `error_message` (Optional[str]): 错误信息
  - `created_at` (datetime): 创建时间
  - `updated_at` (datetime): 更新时间
- **权限表达式**: `accounts:read`

### 2. 创建账号

- **方法**: POST
- **路径**: `/api/accounts/`
- **描述**: 为当前用户创建一个新账号
- **请求体** (`AccountCreate`):
  - `platform` (str, 必填): 平台
  - `nickname` (str, 必填): 昵称
  - `avatar_url` (Optional[str], 选填): 头像 URL
  - `cookie_data` (Optional[str], 选填): Cookie 数据
  - `access_token` (Optional[str], 选填): 访问令牌
  - `token_expires_at` (Optional[datetime], 选填): 令牌过期时间
- **响应体** (`AccountResponse`): 结构同列表项
- **权限表达式**: `account:create:write`

### 3. 获取账号详情

- **方法**: GET
- **路径**: `/api/accounts/{account_id}`
- **描述**: 获取指定账号详情
- **路径参数**:
  - `account_id` (str): 账号 ID
- **响应体** (`AccountResponse`)
- **权限表达式**: `accounts:read&isOwnAccount(account)`

### 4. 更新账号

- **方法**: PUT
- **路径**: `/api/accounts/{account_id}`
- **描述**: 更新指定账号信息
- **路径参数**:
  - `account_id` (str): 账号 ID
- **请求体** (`AccountUpdate`, 均选填):
  - `nickname` (Optional[str])
  - `avatar_url` (Optional[str])
  - `status` (Optional[str])
  - `cookie_data` (Optional[str])
  - `access_token` (Optional[str])
  - `token_expires_at` (Optional[datetime])
- **响应体** (`AccountResponse`)
- **权限表达式**: `account:update:write&isOwnAccount(account)`

### 5. 删除账号

- **方法**: DELETE
- **路径**: `/api/accounts/{account_id}`
- **描述**: 删除指定账号
- **路径参数**:
  - `account_id` (str): 账号 ID
- **响应体**: 无（HTTP 204）
- **权限表达式**: `account:delete:write&isOwnAccount(account)`

### 6. 检查账号状态

- **方法**: POST
- **路径**: `/api/accounts/{account_id}/check`
- **描述**: 通过平台适配器检查账号的实时状态
- **路径参数**:
  - `account_id` (str): 账号 ID
- **响应体** (`AccountStatusResponse`):
  - `id` (str): 账号 ID
  - `status` (str): 状态
  - `last_check_at` (Optional[datetime]): 最后检查时间
  - `error_message` (Optional[str]): 错误信息
- **权限表达式**: `account:check:write&isOwnAccount(account)`

### 1. 获取内容列表

- **方法**: GET
- **路径**: `/api/contents/`
- **描述**: 分页获取当前用户的内容列表，可按平台和状态过滤
- **查询参数**:
  - `platform` (str, 选填): 平台过滤
  - `status` (str, 选填, 别名 `status_filter`): 状态过滤
  - `page` (int, 默认 1, ≥1): 页码
  - `page_size` (int, 默认 20, 1~100): 每页条数
- **响应体**: list[`ContentResponse`]
  - `id` (str): 内容 ID
  - `user_id` (str): 用户 ID
  - `title` (str): 标题
  - `body` (str): 正文
  - `platform` (str): 平台
  - `status` (str): 状态
  - `media_urls` (Optional[str]): 媒体 URL
  - `ai_generated` (bool): 是否 AI 生成
  - `original_content_id` (Optional[str]): 原始内容 ID
  - `created_at` (datetime): 创建时间
  - `updated_at` (datetime): 更新时间
- **权限表达式**: `content:read`

### 2. 创建内容

- **方法**: POST
- **路径**: `/api/contents/`
- **描述**: 创建一条新内容
- **请求体** (`ContentCreate`):
  - `title` (str, 必填): 标题
  - `body` (str, 必填): 正文
  - `platform` (str, 必填): 平台
  - `status` (str, 选填, 默认 "draft"): 状态
  - `media_urls` (Optional[str], 选填): 媒体 URL
- **响应体** (`ContentResponse`)
- **权限表达式**: `content:create:write`

### 3. 获取 AI 生成记录列表

- **方法**: GET
- **路径**: `/api/contents/ai-generations`
- **描述**: 分页获取当前用户的 AI 生成记录
- **查询参数**:
  - `platform` (str, 选填)
  - `page` (int, 默认 1, ≥1)
  - `page_size` (int, 默认 20, 1~100)
- **响应体**: list[`AIGenerationRecordResponse`]
  - `id` (str): 记录 ID
  - `user_id` (str): 用户 ID

## 十七、约束管理模块 `/api/v2/constraints`

### 1. 获取约束列表

- **路径**: `/api/v2/constraints`

- **响应体**: list[`ConstraintListItem`]
  - `id` (str): 约束 ID
  - `name` (str): 约束名

  - `constraint_type` (str): 约束类型（mutual_exclusive / prerequisite / cardinality）
  - `config` (dict): 配置
  - `is_active` (bool): 是否启用
  - `created_at` (datetime): 创建时间

## 权限判断函数实现说明

> 完整函数定义、参数规范及使用示例见 [权限表达式内置判断函数](权限表达式内置判断函数.md)。

### 前端实现（`frontend/src/utils/permExpression.ts`）

| 函数              | 参数形式                            | 实现逻辑                                     |
| ----------------- | ----------------------------------- | -------------------------------------------- |
| `isAuthenticated` | 无参                                | 路由守卫已校验，表达式层恒返回 `true`        |
| `isSuperAdmin`    | 无参                                | `currentUser.role == "admin" && currentUser.id == "1"` |
| `isAdmin`         | 无参                                | `currentUser.role in ["admin", "manager"]`   |
| `isSelf`          | 无参(`ctx.user_id`)/有参(`key_name`) | `currentUser.id === ctx[key_name]`           |
| `isBuiltInAdmin`  | 无参(`ctx.user_id`)/有参(`key_name`) | `ctx[key_name] === "1"`                      |
| `isOwnContent`    | 无参(`ctx.content`)/有参(`key_name`) | `ctx[key_name].user_id === currentUser.id`   |
| `isOwnAccount`    | 无参(`ctx.account`)/有参(`key_name`) | `ctx[key_name].user_id === currentUser.id`   |
| `hasSameRole`     | 无参(`ctx.target_user`)/有参(`key_name`) | `current_role_ids ∩ target_role_ids ≠ ∅`     |
| `isAdminType`     | `isAdminType(role_type)`            | 前端暂未实现，由后端约束校验使用             |
| `isOtherType`     | `isOtherType(role_type)`            | 前端暂未实现，由后端约束校验使用             |

### 后端实现（`backend/app/services/perm_expression.py`）

| 函数              | 参数形式                            | 实现逻辑                                     |
| ----------------- | ----------------------------------- | -------------------------------------------- |
| `isAuthenticated` | 无参                                | `current_user` 存在即 `true`（依赖层已校验） |
| `isSuperAdmin`    | 无参                                | `current_user.role == "admin" and current_user.id == "1"` |
| `isAdmin`         | 无参                                | `current_user.role in {"admin", "manager"}`  |
| `isSelf`          | 无参(`ctx["user_id"]`)/有参(`key_name`) | `current_user.id == ctx[key_name]`           |
| `isBuiltInAdmin`  | 无参(`ctx["user_id"]`)/有参(`key_name`) | `ctx[key_name] == "1"`                       |
| `isOwnContent`    | 无参(`ctx["content"]`)/有参(`key_name`) | `ctx[key_name].user_id == current_user.id`   |
| `isOwnAccount`    | 无参(`ctx["account"]`)/有参(`key_name`) | `ctx[key_name].user_id == current_user.id`   |
| `hasSameRole`     | 无参(`ctx["target_user"]`)/有参(`key_name`) | `current_role_ids & target_role_ids ≠ ∅`（后备 `all_role_ids`） |
| `isAdminType`     | `isAdminType(role_type)`            | 由 `rbac_constraint_service` 使用，未注册到 `BUILTIN_FUNCTIONS` |
| `isOtherType`     | `isOtherType(role_type)`            | 由 `rbac_constraint_service` 使用，未注册到 `BUILTIN_FUNCTIONS` |
